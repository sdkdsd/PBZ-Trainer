# 影之刃零修改器 v0.13.1

Windows 64 位修改器，支持中文界面与单文件 EXE。连接时校验游戏版本，所有修改功能默认关闭。

**[下载 v0.13.1](https://github.com/sdkdsd/PBZ-Trainer/releases/tag/v0.13.1)** · [更新记录](CHANGELOG.md) · [验证记录](VALIDATION.md)

修复了一些已知bug

## 下载与使用

1. 打开 Release 页面，在 Assets 中下载 `PBZ-Trainer-v0.13.1.exe`。
2. 进入可以操作角色的场景后双击 EXE，程序会尝试连接游戏。
3. 按需开启功能。无需安装 Python，也不需要额外的配置文件或 runtime 文件夹。

当前支持 **Steam build 26266538** 的 Windows x64 主程序；其他版本需要重新适配。

## 随地传送解锁

**游戏会提示消耗穿行符（传送符），但实际不消耗。** 正常确认即可；已有穿行符记录且数量为 0 时同样可用。

在地图中选择已激活且可传送的目的地。保留游戏原有战斗、剧情及其他可传送条件，不解锁未激活目的地。此开关独立于锁血，关闭传送开关不影响生命保护。

## 功能

| 功能 | 范围与说明 |
| --- | --- |
| 强锁血 | 维持生命下限，与自动回血互斥 |
| 自动回血 | 受伤后补满，不能保证阻止一击致死 |
| 锁杀气、暗源、精纯杀气 | 消耗后按需补满，不改变容量 |
| 锁葫芦／酒次数 | 补满已有药品次数；图标可能需切换快捷药品刷新 |
| 单次补充 | 回满生命、补充葫芦、补满精纯杀气 |
| 玩家基础攻击倍率 | 0.1–20 倍，调整基础攻击，最终伤害由游戏计算 |
| 一键秒杀 | 基础攻击 ×10000，与普通倍率相互替代；特殊敌人及剧情规则仍按游戏处理 |
| 怪物伤害倍率 | 0.1–20 倍，调整玩家物理／元素承伤，不包含特殊真实伤害 |
| 移动加速 | 1–5 倍；冲刺被游戏重算后可能需重新应用 |
| 武器切换冷却 | 0.1–2 秒；换装备后需重新应用 |
| 随地传送解锁 | 会提示消耗穿行符，但实际不消耗 |
| 意识尘埃数量 | 0–2,000,000,000，支持撤销同一窗口上次设置 |

## 场景切换与恢复

强锁血与攻击倍率保留开启请求，加载或角色暂不可读时暂停写入；当前角色稳定后重新绑定。攻击维持本次设置的固定目标，避免重复叠乘。其他资源锁在对象切换时可能停止，需要重新开启。

“恢复移速”只恢复移动速度；底部恢复按钮同时管理倍率、移速、武器切换冷却和生命下限。正常退出会停止本窗口的资源锁，条件恢复本窗口记录的修改及传送分派。意识尘埃可能随自动存档保留，不随关闭回退。新窗口不会接管其他修改器已开启的功能，请勿同时用多个面板控制同一项。

传送校验心跳超过约三秒未更新时转交原游戏行为；适配页保留到游戏退出，避免正在执行的调用访问已释放内存。正常退出会条件恢复对应分派指针。

## 错误提示与恢复（fork 第 4 步新增）

界面底部除原有消息行外，新增一行**错误状态栏**，颜色取当前最高等级：

| 颜色 | 等级 | 含义 | 程序做了什么 / 你该怎么做 |
| --- | --- | --- | --- |
| 不显示 | 目标失效 | 切场景、角色未就绪、对象已切换等暂时情况 | 自动等待重新绑定，无需处理 |
| 灰色 | 日志异常 | `actions.jsonl` 写不进去（磁盘满、无权限） | 修改照常进行，但审计记录可能缺失；检查日志目录 |
| 黄色 | 读取失败 | 连续约 20 次读不到游戏内存 | 确认游戏仍在运行、角色可操作 |
| 黄色 | 写入失败 | 写入失败或读回不一致 | 对应功能已停止或停用，需要时重新开启 |
| 红色 | 版本校验失败 | 游戏版本或映像与已核对版本不符 | 拒绝连接，不会写入；需要新版适配 |
| 红色 | 回滚失败 | 写入失败后，恢复原值也失败，**游戏里可能残留修改** | 首次出现会弹窗；撤销记录已保留，按下面步骤恢复 |

- 状态栏显示各类计数和最近一条；点 **“详情”** 查看最近 5 条。
- 红色提示**不会被普通消息覆盖**，必须点 **“已知晓”** 才会清除。“已知晓”只清除提示，不会改动游戏数据。
- 出现回滚失败时，点 **“恢复残留修改”**（与底部“恢复倍率、移速、冷却与锁血”相同）重试恢复已保留的记录。已恢复的条目会从记录中删除，重复点击不会重复写入。恢复仍然失败时，消息行会列出每一项的原因；也可以等角色稳定后再试，或查看日志。
- 强锁血、攻击倍率因写入或回滚失败被停用时，状态文字显示“已停用”，强锁血开关会自动取消勾选；确认问题后重新开启即可。只有角色暂不可读时才显示“暂缓”，并在角色稳定后自动继续。

EXE 日志保存在 `%LOCALAPPDATA%/PBZTrainer/logs/actions.jsonl`；源码模式使用源码目录的 `logs/`。

## 从源码运行与构建

使用带 Tk 的 Windows x64 Python 3.13：

```powershell
python app.py
python app.py --preview
```

构建单文件 EXE：

```powershell
python -m venv .build-venv
& ./.build-venv/Scripts/python.exe -m pip install -r requirements-build.txt
./build_exe.ps1
```

输出为 `dist/影之刃零修改器.exe`，内含运行环境、版本配置、原创图标及许可。

本地检查：

```powershell
python -m unittest discover -s . -p 'test_*.py'
python app.py --self-check --report ui-check.json
```

自检不连接游戏；`--check-game` 额外进行阻断写入的只读连接检查。许可证可在“使用说明”中查看，原文见 [THIRD_PARTY_NOTICES.txt](assets/THIRD_PARTY_NOTICES.txt)。

## 持续集成（fork 第 8 步新增）

本 fork 在 GitHub Actions 上用 **windows-latest + Python 3.13** 自动跑测试。

| 触发 | 跑什么 |
| --- | --- |
| push 到 `main` / `master` / `step*`，或打开/更新 PR | **test**：全量 `unittest` + `app.py --self-check` |
| 手动 `workflow_dispatch`，或推送标签 `v*` | 上述 test，外加 **build**：`build_exe.py` 产出 EXE |

- Actions 页可下载 artifact：`ui-check`（自检 JSON，失败也会尽量上传）；手动打包时还有 `pbz-trainer-exe`（EXE + `build-report.json`，含各输入文件 SHA256，保留 14 天）。
- **CI 绿 ≠ 实机已验收。** 流水线不装 Steam、不连游戏、不跑修改功能实机验收；只验证假内存单测与界面自检（开关默认关闭等）。游戏内行为仍需在 Windows 上人工确认。
- 权限仅 `contents: read`；不会自动发 Release，也不会向原作者仓库提 PR。
